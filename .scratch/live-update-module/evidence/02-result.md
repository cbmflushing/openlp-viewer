# Ticket 02 result

The production viewer now creates one `createLiveUpdate({ onData: displayLiveData, onError: displayLiveError })`, starts it with the loaded server, and calls `switchServer` on a changed saved server or reset. The old global request version, polling, refresh coalescing, socket/discovery/reconnect and request-timeout implementation is removed. Module state stays private; the standalone page has no new dependency or build step. The existing module interface and implementation were not changed.

`displayLiveData` owns selected-slide interpretation, parsing, language filtering, title/footer, fitting and fade. It deliberately catches presentation exceptions and invokes the same error presenter as network failures; callback exceptions thus do not leak as unhandled module promise rejections. Empty successful data still clears/fades; request failure leaves current content/fade intact and displays the error. Stale error suppression belongs to the module. Local blackout remains independent.

## Coverage migration

- `test_viewer.cjs` now invokes the actual module through its polling timer rather than bypassing it via the deleted `fetchAndDisplay`. Existing parsing, title/footer, settings, fade and blackout assertions remain; current error reporting, recovery and presentation exceptions are explicitly checked.
- `test_websocket.cjs` exercises the real module with a lifecycle spy and production presentation: saved/default startup, unchanged and changed server saves, stale failure, push and Blob updates, coalescing, fallback polling, reset and reconnect cleanup. Timing and races formerly coupled to viewer globals are tested on the public module interface in `test_live_update.cjs`.

Added explicit malformed/rejected Blob, disconnected-socket delayed decode, aborted hung fetch and push-superseded error checks. The former pair of concurrent direct `fetchAndDisplay` calls has no public equivalent: module refreshes are coalesced; the push-supersession checks assert that older results cannot overwrite fresher data instead.
- `test_layout.cjs` drives actual module polling and keeps all real-browser presentation/layout assertions, including unchanged DOM, resizing, font loading and blackout. `test_colors.cjs` remains unchanged. Python integration comments now name the presentation function.
